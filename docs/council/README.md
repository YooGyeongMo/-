# 협의체 운영 규칙 (REQ-25)

> 확정: 2026-09-21 협의체 1차 세션(FD-8 협의체 절, PM-5 채택). 이 폴더는 `docs/council/S{n}.md`(세션 기록)·`S{n}-redteam.md`(레드팀 판정)·`S{n}/`(파트 메모 원문)으로 구성한다. 결정의 단일 원본은 각 세션의 `S{n}.md` FD 목록이고, 최종 형태는 ADR이다.

## 1. 구성
PM(일정·범위) · PO(제품·REQ 대장 소유) · AI · iOS · macOS·iPad · Backend · QA · **레드팀 1~2**(역할 고정 아님, 매번 다른 관점: 기술 타당성·아키텍처 / 일정·비용·프라이버시·운영 중 지정). 레드팀은 결정을 **바꾸지 않고 등급만 매긴다**. 최종 결정권은 사용자.

## 2. 소집 시점 (셋 중 하나)
1. **정기**: 각 스프린트 **마지막 날 오후**(데모 직후) = 다음 스프린트 킥오프. 9/26(S0 킥오프는 9/21 선행)·10/2·10/9·10/16·10/23·10/30 + 11/6 릴리스 레드팀.
2. **설계 변경**: REQ 신설·상태 변경, 계약 v1.1 항목 추가, D-n/T-xx/ADR 결정 번복, 크리티컬 패스 이슈 1일 이상 지연.
3. **데모 실패**: 스프린트 목표(16번 §3 "목표(데모)")가 녹화되지 않음.

## 3. 입력
BRIEF(공통 브리핑, 사용자 답변 포함) · 직전 스프린트 로그(`docs/log/`) · 번다운(닫힌 이슈/계획) · 미결 "확인 필요" 목록 · `docs/REQUIREMENTS.md` · 직전 세션 `S{n-1}.md`의 미해소 항목.

## 4. 산출물
- `S{n}.md`: 참여 역할, 의제, 파트별 핵심 결정 요약(각 5줄 이내), 사용자 결정 원문, **FD 목록**(Final Decision, 단일 원본). 결정 ≥ 1개, 각 결정은 **REQ-20 7항목**(의도 → 비용 → 대안 ≥ 2 + 탈락 이유 → 왜 → 영향 파일·문서 → 검증(숫자·테스트 이름) → 리스크·되돌리는 조건(신호·임계값)). **형식이 빠진 결정은 무효**(1차 세션에서 AI-5·AI-6·MN-3·MN-4·B-6 ②·QA §2-2/2-3/§4가 무효 판정 → ADR에서 재작성).
- `S{n}-redteam.md`: 결정별 등급표 + 한 줄 사유 + 사실 검증 표(Apple 문서 등 출처·확인일). 5줄 요약은 `docs/log/`.
- `S{n}/`: 파트 메모 원문 **그대로 복사**(사용자: "빠짐없이 기록"). 요약본이 원문을 대체하지 않는다.
- 이슈 변경표(유지/수정/추가/삭제=v1.1 이관) + 마일스톤·GitHub Project #2 반영은 PM이 `gh`로 당일 수행. v1.1 이관은 이슈를 닫지 않고 `sprint:v1.1` 라벨(REQ-34).
- ADR 번호 예약. 그림이 필요한 결정은 archify 1장 링크(REQ-24). 배운 점은 `docs/lessons/`(REQ-21).

## 5. 레드팀 기준 (각 결정마다, **치명 0이어야 킥오프**)
| 등급 | 기준 |
|---|---|
| 치명 | REQ 대장 위반 / 계약 v1.0 변경 요구 / 시크릿·원문 유출 경로 / 유료 결제 발생 경로 / 1인 견적이 스프린트 잔여 시간 초과 / **같은 문제에 파트마다 다른 답**(1차 세션 치명 8건 중 5건이 이 유형) |
| 중요 | 대안 < 2 또는 탈락 근거 없음 / 검증이 측정 가능하지 않음 / 되돌리는 조건에 신호·임계값 없음 / Apple API 가용성이 문서 MCP로 확인되지 않았는데 "확인 필요" 표기 없음 / 외부 사실을 출처·확인일 없이 "[사실]"로 서술 |
| 경미 | 영향 파일·절 번호 누락 / 견적이 0.5일 단위가 아님 / 표기 불일치 |
치명·중요는 해당 역할이 같은 세션에서 수정, 재판정 1회. 사용자 결정이 필요한 항목(U-목록)은 레드팀이 표로 모아 사용자에게 올리고, 답변 원문을 `S{n}.md`에 그대로 적는다.

## 6. 운영 상한
- 사람 시간 **1.5h/세션**. 결정 수 ≤ 5/세션(넘으면 다음 세션). 에이전트 산출물은 각 2,000자 요약 + 상세 첨부(원문은 `S{n}/`).
- 2회 연속 1.5h 초과 → **격주**로 완화하고 REQ-25 상태·날짜를 갱신한다.
- 문서 시간이 하루 1h를 넘기 시작하면(PM 리스크 5) 그림은 "구조·흐름·결정이 바뀐 이슈"만, ADR은 한 문단 허용(16번 §1-3).

## 7. 단일 원본 규칙 (1차 세션 교훈)
- 여러 파트가 같은 파일·스키마·수치를 다루면 **소유자 1명 + 파일 1개**를 세션 안에서 먼저 정한다. 예: `contracts/push-payload.schema.json`(macOS·iPad → Backend가 구현), `eval/`(AI), `eval/limits.md`(무료 한도의 유일한 출처, AI), 스냅샷 매트릭스(QA), 무료 한도 초과 정책(Backend), 비용 모델 입력(PO 계산 + Backend `usage_daily`).
- 다른 파트 메모의 숫자·스키마는 그 파일을 **인용**만 한다. 파트 메모끼리 다르면 `S{n}.md` FD가 이긴다.
- 파트가 자기 v1.0 항목을 PM 표의 Day 번호에 **직접 매핑**한 뒤(Day에 못 붙는 항목 = 자동 v1.1) PM이 재합산해 "순증 ≤ 감축"을 증명한 합산표 1장을 낸다. 파트 견적 합산 없이 PM 견적을 신뢰하지 않는다(RT-B-01).
- 무료 티어·외부 서비스 약관은 **기능 결정 전에** 읽고 ADR 부록에 인용·URL·확인일을 남긴다(ADR-0008 부록 A).
