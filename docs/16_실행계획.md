## 3. 합산표 (RT-B-01 대응: 파트 요구 → 컷 → 잔여 → 34일 이내 증명)

### 3-1. 달력 검증 (`cal 9 2026; cal 10 2026; cal 11 2026`, 2026-09-21 실행)
- 9/22는 **화요일**, 9/26은 **토요일**(v1 문서의 "9/22(월)"·"Day 5 = 9/26"은 오기 → 정정). 11/6은 금요일, 11/13은 금요일.
- 9/22(화)~11/6(금) = 46일, **평일 34일**, 주말 12일. 공휴일 평일 5일(9/24 추석 연휴·9/25 추석·9/28 대체공휴일·10/5 개천절 대체·10/9 한글날)은 **전부 근무**(사용자 답변 2026-09-19).

**소집** (셋 중 하나): ① 정기 = 각 스프린트 **마지막 날 오후**(데모 직후) = 다음 스프린트 킥오프: Day 4(9/25), 9(10/2), 14(10/9), 19(10/16), 24(10/23), 29(10/30) + Day 34(11/6) 릴리스 레드팀. ② 설계 변경: REQ 신설·상태 변경, 계약 v1.1 항목 추가, D-n/T-xx/FD-x 번복(ADR "폐기"), 크리티컬 패스 1일 이상 지연. ③ 데모 실패: §4 "목표(데모)"가 녹화되지 않음.
**입력**: `docs/council/S{n-1}.md`, 직전 로그, 번다운, "확인 필요" 목록, 실제 작업 시간 합계(§3-3 검증).
**산출물**: `docs/council/S{n}.md`(결정은 REQ-20 7항목, 형식 미달은 무효) + `S{n}-redteam.md`(등급표). 이슈 변경표 → 보드 반영은 PM이 당일. 그림이 필요한 결정은 archify 1장.
**레드팀 기준**: 치명 = REQ 위반 / 계약 v1.0 변경 / 시크릿·원문 유출 경로 / 유료 결제 / 1인 견적이 잔여 시간 초과. 중요 = 대안 < 2 / 검증 불가 / 되돌림 임계값 없음 / Apple API 미확인인데 "확인 필요" 표기 없음. 경미 = 형식. **치명 0이어야 킥오프.** 재판정 1회.
**상한**: 사람 시간 1.5h/세션, 결정 ≤ 5/세션, 에이전트 산출물 각 2,000자 요약 + 첨부. **2회 연속 1.5h 초과 → 격주로 완화**하고 REQ-25 상태를 "협의 중"으로 바꿔 날짜를 기록한다.

## 7. 매일 같은 순서
1. 오늘 Day의 이슈를 `Doing`으로. 브랜치 `s{n}/{영역}-{요약}-#{이슈}`.
2. API·라이브러리는 문서 MCP로 **최소 OS 기준** 확인(추측으로 코드 쓰지 않음).
3. 테스트 먼저 또는 함께. 커밋 작게, §2-2.
4. PR: 셀프 리뷰, CI 초록(카나리 포함), squash 머지.
5. `docs/log/오늘.md` 5줄 + 작업 시간(h). 트레이드오프가 있었으면 ADR.
6. 보드 `Done`, 내일 Day 확인. 밀린 항목은 "밀림" 라벨 대신 Day 필드를 옮기고 로그에 이유.
7. 스프린트 마지막 날: 데모 녹화 → 협의체(§6) → lessons → 마일스톤 닫기.
