### 1-2. Sentry와 Amplitude의 목적 (섞지 않는다)
| | Sentry | Amplitude |
|---|---|---|
| 질문 | "깨졌나, 느린가, 어디서" | "쓰나, 돌아오나, 어디서 떠나나" |
| 데이터 | 크래시, 처리된 에러(DomainError.unknown 등), 성능 트랜잭션 4개, breadcrumb(탭 이름만), release health(크래시 프리 세션) | 이벤트 15개(12번 §10), 사용자 속성(등급·직군·플랫폼), 퍼널 4개, 리텐션(7일 스트릭) |
| 앱·서버 연결 | `X-Request-Id` 태그로 서버 로그와 결합 | 서버는 보내지 않음(클라이언트 이벤트만) |
| 금지 | 원문·받아쓰기·바디·PII | 텍스트 속성 전부 |
| 대시보드 | 릴리스별 크래시율, p95 지연, 에러 상위 5 | 온보딩 완료율, 첫 해석까지 시간, 카드 전환율, 7일 리텐션, 마감 전 완료율 |
| 알림 | 새 이슈·회귀·크래시 프리 < 99% | 주간 리포트 |
| 옵트아웃 | A-09 토글로 둘 다 no-op | 같음 |

## 2. 기록 형식 (공통, 예외 없음)

### 2-1. Issue
제목: `[S1][app] 로그인 화면 S-01 (Apple 웹세션)` — `[스프린트][영역]`, 영역 ∈ app, server, contracts, infra, docs, qa.
본문(템플릿 `task.yml`): 목적(한 줄) / 범위(이 이슈에서 하는 것·안 하는 것) / 완료 기준(체크박스, 테스트 포함) / 트레이드오프(선택지·결정·ADR 링크, 없으면 "없음") / 관련 문서(설계 §) / 화면 ID / 예상 시간.
라벨: `area:*`, `type:feat|fix|chore|docs|test|adr`, `sprint:S0..S6`, `size:S|M|L`, `blocked`.
프로젝트 필드: Status(Todo/Doing/Review/Done), Sprint, Area, Size, Day(계획일).

### 2-2. 브랜치·커밋·PR
- 브랜치: `s1/app-signin-#23` (`스프린트/영역-요약-#이슈`).
- 커밋: Conventional Commits, 스코프 = 모듈/서비스. `feat(app/Presentation): S-01 로그인 화면 (#23)`. 본문 3줄: 왜 / 무엇 / 테스트. 트레이드오프가 있으면 `ADR: 0007`. AI 공동 저자 표기 없음.
- PR: 제목 = 최종 커밋 제목(squash merge). 본문 템플릿: 요약 / 이슈(`Closes #23`) / 변경 / 트레이드오프(ADR 링크) / 테스트(무엇을 어떻게) / 스크린샷·녹화(화면 변경 시 필수) / 체크리스트(린트·테스트·문서·계약 해시). 셀프 리뷰 코멘트 최소 1개(자기 코드에서 의심스러운 곳).
- 머지: squash, CI 초록, `Closes #n`으로 이슈 자동 종료.

### 2-3. ADR (`docs/adr/NNNN-제목.md`)
상태(제안/채택/폐기) / 맥락 / 선택지(각각 장단점) / 결정 / 근거 / 결과(무엇이 쉬워지고 어려워지나) / 되돌리는 조건 / 관련 이슈·PR. 15번 문서의 결정을 옮기는 것부터 시작(0001~).

### 2-4. 일별 로그 (`docs/log/YYYY-MM-DD.md`)
오늘 한 것(이슈 번호) / 막힌 것과 푼 방법 / 내일 / 결정·발견(ADR 후보). 5줄이면 된다. 없는 날은 만들지 않는다.

### 2-5. 릴리스 노트
태그 `app/v1.0.0`, `server/v1.0.0`. GitHub Release 본문 = 마일스톤 닫힌 이슈 목록(자동) + 체크리스트 통과 기록.
