# 12. 뭔말인교? 앱 아키텍처 설계 v2 (iOS + macOS, MVVM-C + Clean + SDK)

> v2 (2026-09-17): 레드팀 4개(구조·Coordinator / 동시성·API 계약 / SDK·플랫폼 / 테스트·보안·프라이버시) 지적 사항 반영.
> 치명 21건, 중요 38건을 모두 결정으로 바꿨다. 결정은 "결정 D-n"으로 표기하고, 근거를 한 줄씩 붙였다.
> 원칙: **Progressive Disclosure.** 처음 보는 사람에게는 단순하게, 깊이 들어가는 사람에게만 복잡함이 보이게. 화면, SDK API, 코드베이스 세 층에 같은 원칙.
> 기준: Swift 6 (strict concurrency), iOS 26 / macOS 26, SwiftUI만. 서버 계약은 `뭔말인교-API.yml` v1.0 (제출본). 계약을 바꿔야 하는 항목은 §13 "yml v1.1 백로그"에 모아 두고, 앱 v1.0은 v1.0 계약으로만 동작하게 설계했다.

## 0. 한 장 요약

```
앱 타깃 (얇음)                MwonmalKit (SPM, 모든 코드)
┌──────────┐ ┌──────────┐    ┌────────────────────────────────────────────────────────────┐
│ iOS App  │ │ macOS App│ →  │ Composition   조립: AppContainer, 루트 씬, 폰트 등록          │
└──────────┘ └──────────┘    │   ├─ Navigation    TabCoordinator(탭당 경로 1개), 흐름 팩토리   │
                             │   ├─ Presentation  ViewModel + View (흐름별 8 폴더) + Contracts │
                             │   ├─ Domain        Entity, Rules, UseCase, Repository 프로토콜  │
                             │   ├─ Data          Repository 구현, ServerError→DomainError, 캐시│
                             │   ├─ MwonmalAPI    yml에서 생성 + 미들웨어 3개 + KST 날짜 변환   │
                             │   ├─ Platform      Speech, Vision, OAuth 웹세션, Push, Keychain │
                             │   └─ MwonmalUI     디자인 시스템 SDK (SwiftUI만 의존)            │
                             └────────────────────────────────────────────────────────────┘
의존 방향 (SPM 타깃 간, 순환 없음):
  Composition → Navigation → Presentation → Domain
  Presentation → MwonmalUI               (MwonmalUI는 SwiftUI만 import, Domain을 모른다)
  Data → Domain, Data → MwonmalAPI, Data → Platform(프로토콜 구현체 주입은 Composition)
  Platform → Domain (프로토콜 구현)
```

**결정 D-0. 웹(W-xx) 10장은 macOS 네이티브 앱으로 구현한다.** 기획서·API의 "웹"은 화면 설계 기준이고, 구현은 SwiftUI 하나로 두 플랫폼을 만든다. 근거: 같은 ViewModel 재사용, 온디바이스 음성 인식, 서버 계약은 그대로. API `DevicePlatform`에 `MACOS`가 없으므로 v1.0 앱은 macOS 기기를 등록하지 않고(알림 정책 §8-2), v1.1 계약에 `MACOS`를 추가한다(§13).

세 문장으로:
1. **Domain이 중심.** 서버도, 화면도, 애플 프레임워크도 모른다.
2. **경로는 탭이 소유.** 흐름 Coordinator는 화면 팩토리이고, 경로 배열은 탭당 하나다. iOS와 macOS가 같은 상태를 쓴다.
3. **SDK는 값만 받는다.** Domain을 모르고, 문자열을 갖지 않고, 색만으로 뜻을 전하지 않는다.

## 1. Progressive Disclosure 세 층

### 1-1. 사용자 화면 (UX)

**결정 D-1. 규칙은 "첫 스크롤에 Primary 행동 1개 + Secondary 1개까지".** (A-11 "판교어 해석·새 회의", W-07 "회의 녹음·해석 추가"가 둘 다 있어야 하므로.)
**결정 D-2. macOS(넓은 화면)는 펼치고, iPhone은 접는다.** 넓은 화면에서 접는 것은 progressive가 아니라 regressive.

| 화면군 (Presentation 폴더) | iPhone 첫 화면 | iPhone 한 번 더 | 깊이 | macOS |
|---|---|---|---|---|
| Onboarding (O, S-01, S-00-x) | 한 장에 질문 하나 | 건너뛰기(허용된 단계만) | | 같은 흐름, 창 가운데 카드 |
| Home (A-01, A-13, W-08) | 오늘 복습 N장, 할 일 N개, 프로젝트 칩 | 프로젝트 바꾸기 시트(A-10) | 등급 진행률 | 사이드바 + 오늘 요약 전부 |
| Project (A-11, W-00) | 회의 목록 + 버튼 2개 | 할 일 탭, 모르는 말 탭 | 회의 밖 해석 목록 | 세 열 동시 |
| Meeting (A-12, W-07) | 제목, 녹음 상태, 해석 목록 | 받아쓰기 전문 | 해석별 할 일, 용어 칩 | 전문 + 할 일 + 용어 동시 |
| Translate (W-01, A-06/W-03) | **쉬운 말 + 할 일(체크·마감 스위치)** | 숨은 뜻, 용어 칩 | 원문 형광펜, 확신도 | 4블록 전부 |
| Review (A-03/04, W-05) | 단어 + **출처 칩(프로젝트·회의)** | 힌트 | 뒷면: 뜻, 들은 문장, 자기 평가 | 카드 목록 + 필터 |
| Quiz (A-07/08) | 문제 하나 | | 결과: 등급 계단, 틀린 말 담기 | 같음 |
| My (A-09) | 등급, 복습 알림 시간, 마감 알림 스위치 | 진단·사용 데이터 보내기 토글, 로그아웃 | | macOS는 Settings 씬 |

**접지 않는 것 (어느 층에도 숨기지 않음)**: 녹음 동의 체크(매 녹음마다, 자동 체크 금지), 녹음 중 표시(● + 경과 시간, 앱 전역 인디케이터), 건너뛰기 버튼(S-00-1), 오류와 재시도, 로그인 유도.
설정 항목은 API에 실재하는 것만 적었다(`reminderHour`, `actionAlertEnabled`, 기기 해제). 계정 삭제·기기 목록은 v1.1(§13).

### 1-2. SDK API (개발자)

기본 호출은 인자 하나, 옵션은 modifier. **결정 D-3. modifier 구현 방식은 두 가지로 고정한다.**
- Primitives(`MwButton`, `MwChip` …)의 스타일 옵션: **Environment 방식** (`@Entry var mwStyle`), 컨테이너에 붙이면 아래로 전파.
- Domain 컴포넌트의 옵션·콜백: **자기 복사본 방식** (`func onJargonTap(_:) -> JargonText`). 클로저·존재형은 Environment에 넣지 않는다(매 렌더 재평가 방지).

```swift
JargonText(sentence)                                   // 1단계
JargonText(sentence, terms: ranges)                    // 2단계: 서버 startIndex/endIndex 그대로
    .jargonStyle(.highlight)
    .onJargonTap { termId in ... }                     // 3단계
```
UseCase도 같다: `translate(text)` 하나로 되고 `TranslateOptions(projectId:meetingId:direction:inputSource:)`는 필요할 때만.

### 1-3. 코드베이스 (구조)

폴더가 읽는 순서대로 보인다. `Domain/`(파일 30개 안팎)만 읽으면 서비스가 뭔지 안다.

```
MwonmalKit/Sources/
  Domain/  Presentation/  Navigation/  Data/  MwonmalAPI/  Platform/  MwonmalUI/  Composition/
MwonmalKit/Tests/           Domain·Data·Presentation·Navigation·Snapshot·Contract
MwonmalUICatalog/           별도 실행 타깃 (iOS·macOS), 앱에 포함되지 않음
```
**결정 D-4. 흐름 8개는 폴더가 아니라 규칙으로 격리한다.** Presentation은 타깃 하나. "흐름 간 import 금지"는 SwiftLint `custom_rules`(폴더 간 타입 참조 정규식)로 CI에서 강제한다. 흐름별 타깃 분리는 Navigation이 8개를 import하게 되어 v1에서는 하지 않는다.

## 2. Domain (순수 Swift, Foundation만)

```
Domain/
  Entities/     User, Level, Project, Meeting, Recording, Translation(+meetingId?, projectId), ActionItem(dueAt?),
                DetectedTerm(termId?), Card, ReviewSession, ReviewCard, ReviewLog, Quiz, QuizResult, Term, Page<T>
  Rules/        LevelTable(점수→등급), StreakRule, HighlightRange(문자 인덱스→AttributedString 범위), Clock 프로토콜
  UseCases/     프로토콜 + 기본 구현 (§2-1)
  Repositories/ 프로토콜만
  Errors/       DomainError (§5)
  Services/     TranscribingService, OcrService, PushService, TokenStore, AudioCaptureService, OAuthCodeProvider (프로토콜)
```
- Entity는 `Sendable, Identifiable, Equatable, Codable`(경로 복원용). DTO는 Data 밖으로 나오지 않는다.
- **결정 D-5. SM-2 간격 계산은 로컬에 두지 않는다.** `ReviewCard`에 easeFactor가 없어(yml) 계산 불가. 다음 간격은 서버 응답을 믿는다. `Rules/`에는 서버 없이도 검증 가능한 것만 둔다.
- `Clock`은 주입한다(테스트에서 TTL·스트릭 날짜 고정).

**결정 D-8. 앱 v1에는 게스트(비로그인) 모드가 없다.** 로그인 후 사용. 따라서 429 GUEST_QUOTA_EXCEEDED 처리는 앱에 없고, `X-Guest-Id` 같은 식별 수단도 만들지 않는다.
**결정 D-9. 소셜 로그인은 세 제공자 모두 authorization code 흐름.** Apple은 `AuthenticationServices`(코드 반환), 카카오·Google은 `ASWebAuthenticationSession`(REST OAuth, 커스텀 스킴 콜백). 벤더 SDK를 쓰지 않으므로 macOS에서도 같은 코드가 돈다. yml의 `code + redirectUri` required와 정확히 맞는다.

## 3. Data

```
Data/
  Repositories/   10개 구현 (§2-1의 op를 감싼다)
  Mapping/        DTO ↔ Entity, 한 파일에 한 Entity. PagedResponse(allOf value1/value2) → Page<T> 한 곳
  ServerError/    ServerError(status, code, message, field) → DomainError 매핑 함수 하나 + 30코드 표
  Cache/          LevelsCache(actor, TTL 24h) — 캐시는 이것뿐
  Session/        TokenStore 구현(Keychain) + 401 신호 AsyncStream
  Demo/           발표 목업 데이터 + 시나리오 3종(empty, aiDown, conflict) — Fake Repository용 픽스처
```

**결정 D-10. 캐시는 `/levels` 하나.** 복습 카드 파일 캐시는 삭제(복습은 서버 세션 + 답안 POST라 오프라인 불가, "동기화 없음" 원칙과 모순). 용어(`TermDetail`)는 `inMyCards` 같은 사용자 상태가 섞여 캐시하지 않는다. "서버가 진실" = 화면 복귀 시 `.task(id:)`로 refetch, 목록은 pull-to-refresh. 무효화 규칙: AnswerCard 후 홈 `dueCount`, ToggleAction 후 `openActionCount`, SaveCards 후 `unknownTermCount`는 각 화면이 나타날 때 다시 읽는다.

**결정 D-11. Session은 상태를 가진다.** "Repository는 상태 없음" 규칙의 예외. `TokenStore`는 actor, 미들웨어(`Sendable`)가 읽는다. 401은 `AsyncStream<Void>`로 Composition의 `AppCoordinator`에 전달하고, **dedupe**(동시 401 여러 개 → 신호 1개)한다. `oauthLogin`의 401(OAUTH_CODE_INVALID)은 로그인 화면 에러이지 재로그인 신호가 아니다(operationId로 제외).

## 4. MwonmalAPI (생성) + 날짜 + 재시도

- `swift-openapi-generator` + `swift-openapi-urlsession`, 입력은 yml 그대로, 생성물은 커밋하지 않음(빌드 플러그인). CI는 `-skipPackagePluginValidation`.
- 미들웨어는 정확히 3개: `AuthMiddleware`(Bearer, `TokenStore` 읽기), `ErrorMiddleware`(status ≥ 400이면 바디를 `Components.Schemas.Error`로 디코드해 `ServerError` throw), `RetryMiddleware`.
- **결정 D-12. 자동 재시도는 GET만, 503 1회.** POST(createTranslation, startQuiz)는 서버가 이미 행을 만들었을 수 있어 자동 재시도 금지 → `aiUnavailable`이면 사용자 "다시 시도" 버튼. `Idempotency-Key`는 v1.1(§13).
- **결정 D-13. 날짜는 커스텀 `DateTranscoder`.** yml은 타임존 없는 `2026-09-16T10:22:31`. 기본 `ISO8601DateTranscoder`는 타임존 필수라 **모든 응답과 에러 바디까지 디코딩 실패**한다. `KSTDateTranscoder`(Asia/Seoul 고정, 오프셋 있는 문자열도 허용)를 `Client(configuration:)`에 주입. 요청(`heldAt`)도 같은 형식으로 인코딩. `format: date`(dueDate)는 `String`으로 생성되므로 Mapping에서 파싱.
- nullable + allOf(`jobGroup`, `level`, `intentType`, `nuance`, `myCard`)는 생성 코드가 `value1` 래퍼가 되므로 Mapping에서 언래핑. 0단계에서 **실제로 생성해서 컴파일 확인**을 완료 기준에 넣는다.
- multipart(`uploadRecording`)는 생성기 정식 지원. 조각 파트는 `HTTPBody(data, length: .known(n))`. `swift-openapi-urlsession`은 background URLSession 미지원 → **마지막 조각만** `UIApplication.beginBackgroundTask`로 감싸 완료 보장(iOS). (§7)
- 로깅 미들웨어는 없다. 디버그 로깅은 `#if DEBUG`에서 operationId + status만.

## 5. 에러: 30개 코드 → DomainError

**결정 D-14. 매핑은 HTTP 상태가 아니라 `code` 문자열 우선, 상태는 fallback.** 9개 상태 묶음으로는 행동이 다른 코드가 뭉개진다.

```swift
enum DomainError: Error, Equatable {
  case invalidInput(field: String?, message: String)   // 400 INVALID_INPUT, VALIDATION_FAILED
  case consentRequired                                  // 400 RECORDING_CONSENT_REQUIRED → 동의 시트
  case needLogin                                        // 401 (oauthLogin 제외)
  case oauthFailed(message: String)                     // 401 OAUTH_CODE_INVALID → 로그인 화면 에러
  case forbidden
  case notFound(NotFoundReason)                         // 11종. 딥링크면 홈 복귀
  case conflict(ConflictReason)                         // ALREADY_ONBOARDED→홈, CARD_DUPLICATED→성공 취급,
                                                        // QUIZ_ALREADY_SUBMITTED→결과 로드, EMAIL_ALREADY_REGISTERED→제공자 안내,
                                                        // NICKNAME/PROJECT_NAME_DUPLICATED→필드 에러
  case emptyState(EmptyReason)                          // 422 NO_DUE_CARDS, NO_TEXT_DETECTED, NOT_ENOUGH_TERMS → 에러 아님, 빈 화면
  case tooLarge
  case aiUnavailable                                    // 503 → 다시 시도 버튼
  case cancelled                                        // CancellationError → 아무것도 안 함
  case unknown(String)
}
```
- `init(serverError:)` 한 함수. 매핑 테스트는 yml `Error.code` enum 30개 **전수**.
- 화면 표시는 `Presentation/Common/ErrorPresenter` 한 곳. 서버 `message`는 그대로 띄워도 되는 우리말이지만 행동은 `code`로 정한다.

## 6. Presentation (흐름 8개) + ViewModel 계약

```
Presentation/
  Contracts/    *Coordinating 프로토콜 (Navigation이 구현) — 순환 의존 방지
  Common/       ErrorPresenter, RouteHost, Phase

```
파일 규칙: `{Feature}View.swift` / `{Feature}ViewModel.swift`, 파일 머리에 `// 화면: A-12, W-07`. 공용 화면(회의 상세, 해석 입력·결과, 녹음)은 두 ID를 병기한다. **iOS의 해석 입력은 W-01 Compose를 시트로 재사용**한다(A-11 "판교어 해석" 버튼).

**결정 D-15. ViewModel 계약 (레드팀 반영판)**
```swift
@MainActor @Observable
final class TranslateComposeViewModel {
  var text = ""                              // 입력 필드는 공개 (TextField 바인딩)
  var attachedMeeting: Meeting?
  private(set) var phase: Phase<Translation> = .idle   // Equatable
  var isBusy: Bool { phase.isBusy }

  private let translate: any TranslateUseCase
  private weak var coordinator: (any TranslateCoordinating)?   // weak. unowned 금지
  private var inflight: Task<Void, Never>?                     // 사용자 액션은 VM이 소유·취소

  func submit() {                            // 동기. Button에서 바로 호출
    inflight?.cancel()
    inflight = Task { await run() }
  }
  private func run() async {
    phase = .loading
    do { let t = try await translate(text, .init(meetingId: attachedMeeting?.id))
         phase = .done(t); coordinator?.showResult(t.id) }
    catch is CancellationError { phase = .idle }
    catch { phase = .failed(DomainError(error)) }
  }
  deinit { inflight?.cancel() }
}
```
- 조회(onAppear 로딩)만 `.task`가 취소를 맡는다. 사용자 액션(POST)은 VM이 Task를 들고, 화면을 떠나면 `deinit`에서 취소한다. 취소는 실패로 표시하지 않는다.
- `Phase<T>: Equatable`(`DomainError: Equatable` 전제). View는 `isBusy` 같은 계산 속성만 읽는다.
- Coordinator 프로토콜에는 **내비게이션만** 있다. `saveCards` 같은 UseCase 호출은 VM이 하고 끝나면 `coordinator?.pop()`.
- ViewModel에 `#if os()` 금지. 플랫폼 분기는 View의 레이아웃만.

## 7. 녹음: RecordingSession (앱 수명 actor)

**결정 D-16. `RecordingSession`은 Composition의 `AppContainer`가 소유하는 단일 actor다.** 화면·탭·딥링크와 독립. 불변식: 동시 녹음 1개.

```swift
actor RecordingSession {
  func start(meetingId: Meeting.ID, consent: Bool) async throws      // consent false → .consentRequired
  func stop() async throws -> Recording.ID
  func snapshot() -> RecordingState                                  // 화면 재진입 시 누적 상태
  func updates() -> AsyncStream<RecordingState>                      // bufferingNewest(1), 상태·누적 텍스트
  func levels() -> AsyncStream<Float>                                // 파형 전용, 초당 ~20회
}
```
- 오디오 탭(`AVAudioEngine` 콜백, non-Sendable 버퍼)은 Platform 안에서 두 갈래로 복사한다: ① `SpeechAnalyzer` 입력 스트림(미리보기), ② 60초 파일 writer. 탭 밖으로 버퍼를 넘기지 않는다.
- 조각 업로드는 actor 내부 **직렬 큐**: 첫 조각 202 응답의 `recordingId`가 와야 둘째를 보낸다. 조각 파일은 `temporaryDirectory/recording-{meetingId}/{n}.m4a`에 남기고, 실패하면 순서대로 재전송(최대 3회, 지수 backoff). 202 확인 즉시 파일 삭제. 앱 시작 시 고아 폴더 정리. `isExcludedFromBackup = true`.
- 마지막 조각은 iOS `beginBackgroundTask`로 완료 보장. 녹음 중 백그라운드는 `UIBackgroundModes: audio`.
- 401이 녹음 중에 오면: 조각은 디스크 큐에 남기고 재로그인 후 재개(유실 없음). 토큰 갱신 API가 없으므로(§13) 서버에 액세스 토큰 수명 ≥ 24h를 요청한다.
- 화면 재진입: VM은 `snapshot()`으로 복원 후 `updates()` 구독. `.task`가 끊겨도 누적 텍스트는 actor에 있다.
- 녹음 중 뒤로가기: 확인 다이얼로그. 앱 전역 인디케이터(● + 시간)는 `AppRootView`가 `updates()`를 구독해 그린다.
- macOS: 입력 장치 변경(`AVAudioEngineConfigurationChange`) 시 엔진 재구성. iOS는 `AVAudioSession` 인터럽션. 둘 다 `AudioCaptureService` 구현체 안에서 처리.
- 계약 메모: `durationSec`은 조각 길이가 아니라 **누적**으로 보낸다(서버와 합의, §13). `consentConfirmed`는 모든 조각에 true.

## 8. Navigation: 탭이 경로를 소유한다

**결정 D-17. 경로 배열은 탭당 하나(`[AppRoute]`).** 흐름 Coordinator는 경로를 갖지 않고 "화면 팩토리 + 액션 핸들러"다. A-11 → A-12 → A-06처럼 Project·Meeting·Translate 라우트가 한 스택에 섞이므로 라우트 타입은 공용이어야 한다.

```swift
enum Tab: String, Codable { case home, projects, review, my }
enum AppRoute: Hashable, Codable {
  case project(Project.ID), meeting(Meeting.ID), recording(Meeting.ID), decoding(Recording.ID)
  case compose(Meeting.ID?), result(Translation.ID), term(Term.ID)
  case deck(Project.ID?), reviewCard, quiz(Quiz.ID), quizResult(Quiz.ID)
}
enum AppSheet: Identifiable { case projectPicker, newMeeting(Project.ID), recordConsent(Meeting.ID), compose(Meeting.ID?) }

@MainActor @Observable
final class TabCoordinator {
  var selectedTab: Tab = .home
  var paths: [Tab: [AppRoute]] = [:]
  var sheet: AppSheet?
  var pendingAfterDismiss: (() -> Void)?     // 시트 체이닝
  var pendingDeepLink: DeepLink?
}
```
- **루트 뷰는 하나**: iOS 26 `TabView` + `.tabViewStyle(.sidebarAdaptable)`. iPhone은 탭바, macOS·iPad는 사이드바. `NavigationSplitView`를 따로 두지 않는다. 각 탭 안에 `NavigationStack(path: $paths[tab])`. macOS 첫 화면도 홈(A-01 레이아웃, 사이드바 폭 264).
- 계층: `AppCoordinator`(로그인 여부, 온보딩, 루트 전환, 딥링크 큐, `reset()`) → `TabCoordinator` → 흐름 팩토리 8개(`OnboardingFlow, HomeFlow, ProjectFlow, MeetingFlow, TranslateFlow, ReviewFlow, QuizFlow, MyFlow`). 팩토리는 `@ViewBuilder func makeView(_ route: AppRoute) -> some View`(내부 switch)와 `*Coordinating` 구현(`TabCoordinator`에 위임).
- **VM 재생성 방지**: `navigationDestination` 클로저는 리렌더마다 호출되므로 `RouteHost<VM>`(`@State var vm`) 래퍼로 라우트당 1회 생성. VM은 라우트 수명, 흐름 팩토리와 `TabCoordinator`는 창 수명, `AppContainer`·`RecordingSession`은 앱 수명. (수명표 §8-4)
- 라우트는 ID만 든다. 목적지 화면은 자기 UseCase로 다시 읽고 스켈레톤을 보여 준다(이미 가진 Entity를 넘기지 않는다).
- 상태 복원: `AppRoute: Codable` → `@SceneStorage`에 `paths`·`selectedTab` 저장. 복원 후 `getMe` 실패(401)면 `reset()`.
- 뒤로가기 정책: A-04 자기 평가 중, A-07 시험 중, W-02 녹음 중은 `navigationBarBackButtonHidden` + 확인 다이얼로그. 시트는 `interactiveDismissDisabled`를 W-02a(동의)에만.

### 8-1. 시트 체이닝과 탭 넘김
- SwiftUI는 시트 하나. W-06(새 회의) → "만들고 바로 녹음" = W-06 `onDismiss` → `pendingAfterDismiss`로 W-02a present → dismiss 후 `.recording(id)` push. 순서는 `TabCoordinator`가 갖는다.
- **결정 D-18. A-10(프로젝트 선택 시트)은 이동이 아니라 현재 프로젝트 변경(`updateMe`) 후 dismiss.** 홈이 그 프로젝트로 다시 읽는다. 탭을 넘는 push는 하지 않는다.
- Home에서 복습 시작, MY 진입은 **탭 전환**(`selectedTab = .review/.my`), push가 아니다. W-05 단어장은 `.deck(projectId)`로 Project 탭 스택에 push.
- W-04 해석 중: `.decoding(recordingId)`가 완료되면 `path.replaceLast(.result(id))` (뒤로가기로 W-04에 다시 안 들어감).

### 8-2. 알림과 딥링크 (4종)
- 종류: `REVIEW_REMINDER → (review 탭, [.reviewCard])`, `ACTION_DUE → (projects, [.project(p), .meeting(m)])`, `DECODE_DONE → (projects, [.project(p), .meeting(m), .result(t)])`, `LEVEL_UP → (review, [.quizResult(q)])`. 조상 ID(projectId, meetingId, quizId)가 payload에 없으면 `LoadTranslationUseCase`/`LoadMeetingUseCase`로 보강한 뒤 `paths[tab] = [...]` 통째 교체. payload 계약은 §13.
- `DeepLink.parse(userInfo) -> DeepLink?`와 `DeepLink → (Tab, [AppRoute])`는 **순수 함수**(단위 테스트).
- 타이밍 게이트: 콜드 스타트·로그인 전·온보딩 중 도착 → `pendingDeepLink`에 큐잉, 루트 전환 뒤 소비. 시트 열림 → 먼저 dismiss, 애니메이션 완료 후 교체. **녹음 중이면 배너만** 띄우고 이동하지 않는다.
- iOS 알림 액션(A-05 "지금 복습 / 미루기"): `UNNotificationCategory` 등록과 delegate 응답은 Platform `PushRegistrar`가 맡고 `DeepLink`로 변환한다. 배지는 `getMyStats.dueCount`로 앱 진입 시 갱신.
- **결정 D-19. macOS 알림 정책 (v1.0)**: 계약에 `MACOS`가 없으므로 macOS는 APNs를 등록하지 않는다. 대신 `alertEnabled`가 켜진 할 일의 마감 30분 전은 **로컬 알림**(`UNCalendarNotificationTrigger`)으로 Mac에서 예약한다(서버 스케줄러와 중복 수신은 폰만 APNs이므로 없음). `DECODE_DONE`은 W-04 폴링이 처리, `REVIEW_REMINDER`는 폰 전용(퇴근길). "인앱 배너"는 삭제. S-00-3 알림 설정은 macOS에서 시간만 저장하고 "퇴근길 복습 알림은 휴대폰으로 갑니다"를 표시. v1.1에서 `MACOS` 등록으로 전환(§13).
- `needLogin`: `AppCoordinator.reset()` = 모든 탭 경로·시트 초기화, `RecordingSession` 중단(조각은 디스크 큐 유지), 로그인 화면.

### 8-3. macOS 창·메뉴
- `WindowGroup` 하나, `.defaultSize(1200, 800)`, 최소 폭 1000. **결정 D-20. 창은 하나만**(⌘N 새 창 비활성). 다중 창 Coordinator 문제를 v1에서 제거. 코디네이터 트리는 그래도 창 수명(`@State`)으로 만든다.
- `Settings` 씬 = A-09 (알림 시간, 마감 알림 스위치, 데이터 토글, 로그아웃). `CommandGroup`: ⌘↩ 해석하기(W-01), ⌘N 새 회의, ⌘R 녹음 시작/정지, Esc 시트 닫기.
- W-01 입력: 드래그&드롭(`.dropDestination(for: Data.self)`)과 ⌘V 이미지 붙여넣기(`.onPasteCommand`) → Vision OCR(D-6). iOS는 `PhotosPicker`와 공유 시트.

SDK 규칙
1. 기본 호출은 인자 1개. 옵션은 D-3 방식.
2. **상태 없음, 문자열 없음.** 라벨은 항상 인자로 받는다(로컬라이즈 책임은 앱). v1은 ko-KR 고정, `Localizable.xcstrings`는 만들되 키만.
3. **색만으로 뜻을 전하지 않는다.** 완료 = 체크마크 + 취소선, 마감 = "오늘/내일" 글자, 녹음 중 = ● 점멸 + 텍스트, 정답/오답 = 아이콘 + 라벨. (소유자가 적록 색약. coral #E26D5C vs leaf #5DAE6B 대비 1.18:1, coral vs tangerine 1.14:1은 색으로 구분 불가.)
4. **대비**: 흰 글자는 ocean·ink 위에만. coral·leaf·tangerine·teal 버튼의 글자는 ink. 메타 텍스트 `#A6A0AE`는 `#8A8494` 이상으로 올린다(AA 4.5 미달 교정).
5. **접근성 기본**: `JargonText`는 용어마다 `accessibilityLabel("얼라인, 판교어, 뜻 보기")` + action, `Waveform`은 `accessibilityHidden` + 시간 라벨, 진행률은 `accessibilityValue`, 애니메이션은 `accessibilityReduceMotion` 시 정지.
6. **Dynamic Type**: 토큰마다 `Font.custom(_, size:, relativeTo:)` 매핑(34→.largeTitle, 28→.title, 22→.title2, 17→.body, 15→.subheadline, 13→.footnote). 카드·시트에 `fixedSize` 금지, 높이 고정 금지. macOS는 시스템 글자 크기만 따른다.
7. **결정 D-23. v1은 라이트 고정** (`preferredColorScheme(.light)`). 팔레트가 크림 종이 전제라 다크 토큰이 없다. 다크는 v1.1.
8. **폰트**: Pretendard 정적 OTF 400/500/600/700/800을 `Bundle.module`에 넣고 `MwFont.registerAll()`(`CTFontManagerRegisterFontsForURL`)을 Composition이 **첫 View 이전**에 호출. Variable 폰트는 쓰지 않는다(PostScript 이름으로 weight 지정).
9. `JargonText`의 범위 탭은 `AttributedString` link(`mwjargon://{termId}`) + `.environment(\.openURL)` 가로채기. `HighlightRange`(Domain Rules)가 만든 범위를 Presentation이 `AttributedString`으로 바꿔 넘긴다.

## 10. 서드파티 SDK와 관측 (전략)

**결정 D-24. 넣는 것: Sentry, Amplitude, swift-openapi-generator, swift-snapshot-testing, SwiftLint/SwiftFormat. 넣지 않는 것: Kingfisher(아바타 1장 → `AsyncImage` + `URLCache`), Lottie(`symbolEffect`·SwiftUI 애니메이션으로 대체), Firebase, Alamofire, Rx/Combine, DI 라이브러리, Realm/SwiftData.** 도입 기준: 대체 불가 + 두 플랫폼 공통 + 한 문장으로 이유 설명 가능.

**프라이버시 불변식 (§12 위협 모델과 연결)**
> `sourceText`, `transcript`, `extractedText`, 오디오, 캡처 이미지는 **어떤 SDK로도 나가지 않는다.**

- Sentry: `sendDefaultPii = false`, 세션 리플레이 끔, `beforeSend`/`beforeBreadcrumb`에서 요청·응답 바디 제거, URL은 operationId로 치환, user 컨텍스트는 `userId` 해시만, `tracesSampleRate 0.1`, `getRecording` 폴링은 트레이스 제외. `.aiUnavailable`, `.emptyState`, `.cancelled`는 보내지 않는다(정상 흐름). 디코딩 실패와 `.unknown`만.
- Amplitude: `Analytics/EventTaxonomy.md` v1. 이벤트 15개, 속성 화이트리스트(`termId, level, direction, inputSource, phase, count, seconds, bool`), **텍스트 속성 금지**, IDFA 수집 끔(ATT 불필요), device ID만.
- **이벤트는 View가 아니라 ViewModel 액션 메서드 첫 줄에서** 쏜다(버튼 위치가 바뀌어도 따라가고, Spy로 테스트). "눌렀다"는 퍼널 첫 칸에만, 나머지는 결과·실패·소요 시간.

| CTA (화면) | 이벤트 | 속성 | 재는 법 지표 |
|---|---|---|---|
