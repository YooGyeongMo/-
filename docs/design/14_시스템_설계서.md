# 14. 시스템 설계서 (서버)

> 계약: `뭔말인교-API.yml` v1.0 (43 API), `뭔말인교-DB.dbml` (17 테이블). 이 문서는 그 계약을 **실제로 돌리는 서버**의 설계다.
> 클라이언트: iOS·iPad·macOS 앱(`12_앱_아키텍처_설계.md`). 웹 브라우저 클라이언트는 v1 범위 밖(같은 API를 쓰면 언제든 추가 가능).
> v1.1 (2026-09-21): 협의체 1차 FD-3(알림 payload)·FD-4(원문·오디오 정책)·FD-5(AI 4트랙)·FD-6(비용 모델)·FD-7(라우터·집계)·FD-8(prod = OCI Free) 반영. 지우지 않고 개정한다 — 폐기는 "폐기 2026-09-21 → FD-x/ADR-000x". §15 전면 재작성, §19 신설.

## 0. 서버리스 vs 서버: 서버로 간다

**결정 S-0. 컨테이너 기반 상시 서버(API + 워커 + 스케줄러)로 만든다.** 서버리스(Lambda + API Gateway + SQS + Step Functions)는 쓰지 않는다.

| 기준 | 서버리스 | 상시 서버 | 이 서비스에서 |
|---|---|---|---|
| 긴 작업 | 함수 15분 제한, STT 3~5분 작업을 Step Functions로 쪼개야 함 | 워커가 그냥 돌림 | 60분 회의 녹음 = 조각 60개 STT + 해석 1회. **서버 쪽이 단순** |
| 지연 | 콜드 스타트 0.5~2초 | 없음 | 해석 목표 1.2초(yml `latencyMs`), 홈 진입 시 병렬 3호출. **콜드 스타트가 체감됨** |
| 상태 | 없음. 폴링·큐·레이트리밋을 전부 외부 서비스로 | Redis 하나 | 조각 순서 큐, 3초 폴링, 게스트 없음 → **상태가 작지만 있다** |
| DB 연결 | RDS Proxy 필요(연결 폭주) | 커넥션 풀 | MySQL 17테이블, 트랜잭션 많음 |
| 비용 | 트래픽 0이면 0원, 늘면 예측 어려움 | 월 고정 2~4만 원(VM 1대) | 초기 사용자 수백 명, **고정비가 더 싸고 예측 가능** |
| 로컬 개발 | 에뮬레이터 필요 | Docker Compose `up` 한 번 | 혼자 개발, **재현성 우선** |
| 발표 자료와의 정합 | "API 서버 + 스케줄러 + MySQL" 그림과 다름 | 그림 그대로 | 제출한 시스템 구성도와 일치 |

서버리스가 이기는 지점은 "트래픽 0일 때 0원"뿐이고, 그 대가로 STT 파이프라인이 Step Functions 정의 파일로 흩어진다. 상시 서버 1대가 맞다. 나중에 트래픽이 10배가 되면 §12 확장 경로대로 수평 확장하면 되고, 아키텍처를 바꿀 필요는 없다.

## 1. 스택

**결정 S-1. Python 3.12 + FastAPI.** 근거: OpenAPI가 1급 시민(yml과 라우터가 1:1, `schemathesis` 계약 테스트), async I/O가 AI·STT 호출과 맞고, AI SDK가 가장 성숙하며, 개발자가 이미 쓸 줄 안다. Spring Boot는 팀이 있을 때, Vapor는 앱과 모델을 공유하고 싶을 때의 선택이지만 둘 다 v1에는 과하다.

| 역할 | 선택 | 이유 |
|---|---|---|
| API | FastAPI + Uvicorn (2 workers) | async, OpenAPI 네이티브 |
| ORM·마이그레이션 | SQLAlchemy 2 (async) + Alembic | dbml → 모델 1:1, `alembic check` 게이트 |
| DB | MySQL 8 (utf8mb4) | dbml 계약, `json` 컬럼(quiz choices) |
| 큐·캐시·잠금 | Redis 7 | 작업 큐(ARQ), 레이트리밋, 조각 순서 잠금, 알림 dedupe |
| 워커 | ARQ (asyncio 작업 큐) | STT·해석·문제 생성 같은 긴 작업 |
| 스케줄러 | ARQ cron (워커 안) | 복습 알림, 마감 알림, 30일 삭제 |
| 오브젝트 스토리지 | S3 호환 (로컬 MinIO, prod는 Cloudflare R2 또는 S3) | 녹음 조각, 30일 만료 |
| 리버스 프록시·TLS | Caddy | 자동 인증서, HTTP/2 |
| AI | **EngineRouter**(§15, FD-4·5·7, ADR-0007·0008): prod 사슬 `gemini_free`(**옵트인 사용자 + 무료 한도 내**) → `none`(검수 사전만, 강등). 유료 결제 0(REQ-11). OpenAI·Anthropic은 **평가 전용 운영자 키**(`eval/`, prod 사슬 제외). 폐기 2026-09-21 → FD-4: ~~Claude API (`claude-opus-5`)~~ | 해석·숨은 뜻·할 일(한 호출 4필드 JSON). 문제 오답은 규칙(v1.1 AI) |
| STT | **`whisper_local`**(faster-whisper, CPU, worker 옆 컨테이너)만. 외부 STT(Groq·Gemini 오디오)는 약관 확인 결과를 ADR-0008 부록에 첨부하기 전엔 어떤 사슬에도 없음(FD-4). 폐기 2026-09-21: ~~외부 STT API~~ | 조각 단위 배치 변환, 오디오 외부 전송 0 |
| 푸시 | APNs HTTP/2 (`aioapns`), 토큰 인증 `.p8`, payload = `contracts/push-payload.schema.json`(ADR-0010) | iOS·iPad(v1.0), macOS v1.1, watchOS v2 |
| 관측 | Sentry, 구조화 로그, Prometheus `/metrics` | 앱과 같은 Sentry 조직 |
| 배포 | Docker Compose, **OCI Always Free A1**(dev·prod, §14 개정) | §12 |

## 3. 코드 구조 (Clean, 앱과 같은 층 이름)

```
app/
  api/            라우터 12개 (yml 태그와 1:1), 의존성(현재 사용자), 에러 핸들러(→ Error 스키마)
  domain/         엔티티(dataclass), 규칙(등급표, SM-2, 스트릭), 서비스 인터페이스(AI, STT, Push, Storage)
  usecases/       라우터 하나에 하나 (translate, start_recording, submit_quiz …)
  infra/          SQLAlchemy 모델·리포지토리, Redis, S3, Claude, STT, APNs 어댑터, OAuth 3종
  workers/        ARQ 태스크 + cron
  core/           설정(pydantic-settings), 로깅, 요청 ID, 보안(JWT)
migrations/       Alembic (dbml에서 시작)
tests/            unit · integration(testcontainers) · contract(schemathesis)
openapi.yml       원본 계약 (FastAPI가 서빙하는 스키마와 diff 테스트)
```
의존 방향: `api → usecases → domain ← infra`. 앱과 같은 그림이라 두 저장소를 오가며 읽기 쉽다.
**개정 2026-09-21 (FD-7, Backend B-0)**: 폴더는 **컨텍스트 우선** `app/{identity,workspace,decode,learning,notify}/{api,domain,usecases,infra}/` + 공용 `app/core/`. 층 방향은 그대로(컨텍스트 안에서). `import-linter`가 컨텍스트 간 직접 import를 막고, `learning`(퀴즈 오답)은 `decode/domain/services/engine_port.py`의 Protocol만 import한다. 상세 트리는 §17.

**계약 고정**: FastAPI가 생성하는 스키마를 그대로 쓰지 않고, **원본 yml을 서빙**한다. 라우터·Pydantic 모델이 yml과 어긋나면 CI의 `schemathesis`와 스키마 diff 테스트가 막는다.

## 4. 인증

- **로그인**: `POST /auth/oauth/{provider}` (`code`, `redirectUri`). 서버가 제공자 토큰 엔드포인트에 code를 교환하고(Apple: `id_token` 검증, 카카오·Google: userinfo), `users`에 upsert(`provider + provider_id` 유니크), `AuthResponse{accessToken, user}`를 돌려준다.
- **토큰**: JWT(RS256, `kid` 포함, 키 회전 가능). 클레임 `sub=userId, role, iat, exp`. **수명 24시간**(앱 §7 녹음 유실 방지 합의). refresh 토큰은 v1.1(§11).
- **검증**: 미들웨어가 서명·만료 확인 → 401 `UNAUTHORIZED`. 공개 엔드포인트는 `GET /levels`, `GET /terms/{id}`뿐.
- **권한**: 리소스 소유자 검사(`project.user_id == me`)를 유스케이스 첫 줄에서. 위반은 403 `FORBIDDEN`("내 것이 아니라서 접근할 수 없어요").
- **게스트**: 앱 v1에 없음(D-8). 비로그인 3회 체험 로직은 코드로 남기되(`X-Guest-Id` 헤더 → Redis 카운터, 24h TTL, 429 `GUEST_QUOTA_EXCEEDED`) 앱이 부르지 않는다.

## 5. 핵심 흐름

### 5-1. 해석 (동기, 목표 p95 2초)
```
POST /translations
 1. 검증 (sourceText 1~500자, direction) → 400 INVALID_INPUT(field)
 2. 소유권: projectId/meetingId가 내 것인지 → 403/404
 3. 사전 매칭: terms(APPROVED)에서 source_text 안 용어 탐색 (trie, 메모리 캐시 10분)
 4. 엔진 라우터(§15, 개정 2026-09-21 FD-4·7): 입력 = 옵트인 헤더 `X-Mw-AI-Consent: 1`(없으면 미동의) · 서버 설정 `AI_EXTERNAL_TEXT`(기본 off) · Redis 무료 한도 카운터(일 RPD·분 RPM, 80% 소프트 상한) · circuit breaker · 사용자 일 한도 · 엔진 예산 게이트(80% NUANCE 생략, 95% 강등)
      → 동의 + 한도 내: `gemini_free` 한 호출로 resultText, intentType, nuance{note,tip,confidence}, actionItems[], detectedTerms[] (JSON 스키마 출력, 사전 발췌 프롬프트 캐싱)
      → 미동의 또는 한도·브레이커·게이트로 건너뜀: **강등 `none`** = 사전 trie 매칭만(detectedTerms + 치환문, nuance=null, actionItems=[]; 계약상 합법), `aiModel = "none/dictionary#p1"` → 앱 "간이 해석" 배지(U-9 허용)
      타임아웃 8초, 실패·타임아웃 → 다음 칸 → 사슬 끝이 `none`이면 강등, `ROUTER_ALLOW_DEGRADED=false`면 503 AI_UNAVAILABLE + Retry-After 5 (재시도 없음, 앱이 버튼). `EngineError`에 제공자 응답 본문 금지. 호출마다 `ai_usage` 1행(§19, 텍스트 컬럼 0)
 5. 검수 우선: detectedTerms 중 사전에 있는 용어는 사전 plain_ko로 덮어씀(AI 뜻은 참고), 없는 용어는 termId=null + ai_term_ko/ai_plain_ko 저장
 6. 인덱스 검증: startIndex/endIndex가 실제로 matchedText와 일치하는지 서버가 재계산(AI 인덱스는 믿지 않는다)
 7. 트랜잭션: translations + translation_actions(due_at 계산) + translation_terms
 8. 201 TranslationResponse. 지연 latency_ms, `ai_model = {track}/{model}#p{promptVer}`(FD-5 규약, varchar 50 검증: `gemini/gemini-2.5-flash#p1`, `none/dictionary#p1`, `fm/apple-26.4#p1`) 저장
```
같은 사용자·같은 원문·같은 방향이 10분 안에 다시 오면 저장된 결과를 재사용(AI 비용 절감, `_archify` "같은 문장은 저장해 두고" 항목). 이건 서버 내부 최적화라 계약에 안 보인다.

### 5-2. 회의 녹음 파이프라인 (비동기, 상태 기계)
```
앱: 60초마다 POST /meetings/{id}/recordings (multipart: chunk, consentConfirmed, durationSec 누적, recordingId?)
API:
  첫 조각: consentConfirmed 아니면 400 RECORDING_CONSENT_REQUIRED
           meeting_recordings 생성 (status=RECORDING, consent_confirmed, expires_at = now+30d)
  조각 저장: S3 `recordings/{recordingId}/{seq}.m4a` (seq = Redis INCR, 순서 보장은 앱 직렬 큐 + seq)
  enqueue stt_chunk(recordingId, seq)  → 202 RecordingResponse{status, progress}
Worker stt_chunk:
  STT API 호출 → chunk_transcripts(recordingId, seq, text) (Redis 해시) → transcript = seq 순 join → DB 갱신, progress 갱신
앱: "끝내고 해석" = 마지막 조각 + final=true (또는 별도 신호) → status=TRANSCRIBING
Worker decode_meeting (모든 seq 완료 확인 후):
  전체 transcript → AI (source_type=MEETING_NOTE, 최대 5000자, 넘으면 요약 먼저)
  translations 1건 생성 (meeting_id 설정), meeting_recordings.translation_id 연결 (1:1)
  status=DONE → notifications(DECODE_DONE) 저장 → APNs
  실패: status=FAILED, failure_reason, 앱은 GET /recordings/{id}로 봄. 재시도 3회(지수 backoff), 그래도 실패면 알림 없이 FAILED
앱: W-04가 GET /recordings/{id} 3초 폴링 (ETag로 변경 없으면 304)
```
상태: `RECORDING → TRANSCRIBING → DECODING → DONE | FAILED`. 전이는 유스케이스 한 곳(`RecordingStateMachine`)에서만.
조각 누락(seq 빠짐)이 10분 이상 지속되면 `FAILED(reason=CHUNK_MISSING)`. 서버는 조각을 다시 요청하지 않는다(앱 디스크 큐가 재전송).

### 5-3. 복습 (SM-2는 서버가 계산)
```
POST /reviews/sessions: due_date <= today 카드 최대 20장 (없으면 422 NO_DUE_CARDS) → review_sessions
POST /reviews/sessions/{id}/answers: rating(AGAIN/HARD/GOOD/EASY) → SM-2로 ease_factor, interval_days, due_date 갱신,
   review_logs 기록, 세션 카운트, 마지막 카드면 finished_at + users.current_streak/longest_streak 갱신(오늘 첫 완료면 +1)
```
스트릭 규칙: 하루 1세션 완료 = +1, 하루 건너뛰면 0. 계산은 서버 `domain/rules/streak.py` 한 곳.

### 5-4. 실력 테스트
```
POST /quizzes: 내 카드 + 직군 용어에서 5개(기본) 추출, 부족하면 422 NOT_ENOUGH_TERMS
   정답 보기 = 사전 plain_ko(검수본), 오답 3개 = AI 생성(사전 다른 용어 뜻 섞기, 캐시) → quiz_questions(choices json)
POST /quizzes/{id}/submit: 채점 → score, 등급표(levels min/max_score)로 level_code, best_score 갱신, 올랐으면 levelUp=true
   + notifications(LEVEL_UP) 저장(푸시는 앱이 보고 있으니 보내지 않음), wrongTermIds
   이미 제출 → 409 QUIZ_ALREADY_SUBMITTED (앱은 결과 로드)
```

### 5-5. 알림 (스케줄러)
| 작업 | 주기 | 동작 |

**APNs payload = ADR-0010 단일 스키마**(`contracts/push-payload.schema.json`, draft 2020-12; 예시 `contracts/push-examples/{review_due,action_due,translation_done,level_up}.json`; 빌더 `notify/domain/push_payload.py`): `aps{alert{title, body}, category(= type), thread-id, sound, badge}` + `mw{v:1, type ∈ REVIEW_DUE|ACTION_DUE|TRANSLATION_DONE|LEVEL_UP, deepLink: "mwonmal://…", notificationId, ids…}`. **body에 할 일 문장·원문·transcript 절대 없음**(제목·개수·회의 제목까지만, U-10; 빌더 grep 테스트 + jsonschema CI). `deepLink`가 유일한 행동 계약. 헤더: `apns-collapse-id = {type}:{targetId}`, `apns-expiration`(ACTION_DUE = due_at). `LEVEL_UP`은 저장만. 크기 < 4KB.

## 6. 데이터

- 스키마는 `뭔말인교-DB.dbml` 그대로 Alembic 초기 마이그레이션으로 옮긴다. 이후 변경은 마이그레이션으로만.

## 7. 에러 계약

- 모든 실패는 `Error{code, message, field?, timestamp}`. 30개 코드는 `domain/errors.py`의 enum 하나. FastAPI 예외 핸들러가 `DomainError → HTTP 상태 + Error 바디`로 바꾼다(코드별 상태 표는 yml `components/responses`와 동일).
- `timestamp`는 KST 오프셋 없는 ISO 8601(계약 v1.0). v1.1에서 `+09:00`.
- 검증 오류는 Pydantic 오류를 그대로 내보내지 않고 첫 필드만 `INVALID_INPUT(field)`로 변환한다(앱이 입력칸을 빨갛게 칠할 수 있게).
- 503 `AI_UNAVAILABLE`: AI·STT 타임아웃·5xx. 서버는 재시도하지 않는다(중복 생성 방지). `Retry-After: 5` 헤더는 붙인다.

## 9. 보안

- TLS(Caddy 자동), HSTS, 요청 바디 1MB(해석)·5MB(조각) 제한(413 `PAYLOAD_TOO_LARGE`).
- JWT RS256, 키 `kid` 회전, 만료 24h. OAuth 시크릿·APNs 키·AI 키는 `.env`(sops 암호화)에서만.
- 레이트리밋(Redis 토큰 버킷): 사용자당 해석 30/분, 로그인 10/분/IP. 초과 429 `TOO_MANY_REQUESTS`. **개정 2026-09-21 (FD-7, B-4)**: + 사용자 **일 한도** `MWONMAL_AI_USER_DAILY_TRANSLATIONS`(기본 100). 429는 v1.0 계약 Error description에 없음 → **v1.0은 503 + Retry-After**, v1.1에 `TOO_MANY_REQUESTS` 추가(§11 #14). 제공자 무료 한도 카운터(`ai:quota:*`)는 이것과 별개(§15).
- 입력: 원문 500자·5000자 제한, 파일 MIME 검사(m4a/aac), 이미지 업로드 엔드포인트는 앱이 안 쓰지만 열려 있으므로 10MB 제한.
- 컨테이너 non-root, 이미지 스캔(trivy), 시크릿 스캔(gitleaks), 의존성 월 1회 갱신.
- 감사: 삭제 API(회의·프로젝트·해석) 호출은 감사 로그(누가·언제·무엇, 내용 없이).

## 12. 배포 토폴로지와 확장 경로

**v1.0**: VM 1대(4 vCPU/8GB) — Caddy, API×1(2 workers), Worker×1, MySQL, Redis, (MinIO 또는 외부 R2). Docker Compose. 월 2~4만 원.

**확장 트리거와 다음 단계** (아키텍처 변경 없이 프로세스만 분리):
1. API p95 > 1초 지속 → API 컨테이너 2개 + Caddy 로드밸런싱(같은 VM), 그다음 VM 2대.
2. 큐 적체 > 100 → Worker 컨테이너 늘림(무상태, 바로 가능).
3. DB CPU > 70% → 관리형 MySQL(RDS/Cloud SQL)로 이전, 읽기 복제본.
4. 사용자 5,000+ → 오브젝트 스토리지 외부 고정, Redis 관리형, 그때 Kubernetes 검토(그 전엔 안 함).

**로컬**: `docker compose up` 한 번으로 api·worker·mysql·redis·minio·prism(계약 목 서버) 전부. 시드 데이터는 발표 데모(루나, 스프린트 계획 회의, 얼라인 카드, 60점).

### 15-2. 평가셋 (유일한 라우팅 근거)
- **200문장**(합성 + 검수, **실사용자 문장 0**): A 용어 80 / B 숨은 뜻 50 / C 할 일 40 / D 회의록 30. 직군 분포 개발 40·기획 25·디자인 15·기타 20. dev 50 / test 150(프롬프트 튜닝에 안 봄). v0 = 50문장(Day 11), v1 = 200(Day 23). 파일 `eval/dataset/{v0_50,v1_200}.jsonl`, 해시를 점수표에 기록.
- **정답** = `TranslationResponse`의 AI 생성 부분집합(`resultText, jargonCount, intentType, nuance, actionItems[], detectedTerms[]`), `direction`은 yml enum 그대로(`JARGON_TO_PLAIN` 180 / `PLAIN_TO_JARGON` 20), 인덱스는 유니코드 스칼라 기준(`packages/test-vectors/highlight_ranges.json` 공유). `acceptable` 집합으로 과잉 감점 방지.
- **채점**: 용어 스팬 F1(matchedText·start·end 3중 일치; 인덱스만 틀림은 별도 열) / `termId` 정확 일치 / 쉬운 말·숨은 뜻·신조어 `plainKo` LLM-judge 1~5(루브릭 고정, judge 신뢰도 = 사람 30건 Spearman ≥ 0.7) / `intentType` 정확 일치(acceptable) / 할 일 개수 정확 일치 + `actionText` 매칭 F1(임베딩 cos ≥ 0.75) + `dueHint` 정규화 일치 + `dueAt` ±1h / JSON 유효율 / 거부율. **종합(0~100)** = 스팬 F1 25 + intent 15 + nuance(유무 5 + judge 15) + actions(count 10 + text 10 + due 5) + resultText 10 + JSON 5. 가중치 v1 고정.
- **점수표 열**: `track | provider/model | promptVersion | dataset hash | 종합 | spanF1 | intentAcc | nuanceJudge | actionF1 | dueAcc | resultJudge | jsonValid% | refusal% | p50 ms | p95 ms | 입력토큰 | 출력토큰 | 원가/건(₩, 유료 환산) | 무료 한도 대비 사용 | 오프라인 | 원문 외부 전송 | 측정 기기·날짜`. 위치 `eval/scores/*.md`(커밋), `eval/measured/`는 비공개(.gitignore, 사용자 결정).
- **CI 회귀**(13번 §4): CI는 캐시 재생만(외부 호출 0). 실호출은 개발 Mac에서 야간 40문장 회전·릴리스 200.

## 17. 바운디드 컨텍스트, 이벤트, MSA 분리 조건

**결정 S-4. v1은 모듈러 모놀리스.** 배포 단위는 이미 3개(api, worker, scheduler)이고 코드·DB가 하나다. 컨텍스트는 서로 직접 import하지 않는다(`import-linter` 계약으로 CI 강제).

| 컨텍스트 | 소유 테이블 | 밖으로 내는 것 | 분리 난이도 |
|---|---|---|---|
| identity | users, user_devices, levels | userId, 등급 조회 | 낮음(모두 userId만 앎) |
| workspace | projects, meetings, meeting_recordings | 소유권 조회 | 중 |
| decode | translations, translation_actions, translation_terms, terms, term_examples | `TranslationCreated`, `RecordingDone` | 중(AI·STT 비용 중심, 2순위) |
| learning | cards, review_sessions, review_logs, quiz_sessions, quiz_questions | `QuizSubmitted`, `ReviewFinished` | 중 |
| notify | notifications | 이벤트 소비만 | 낮음(1순위 분리 후보) |

**통신은 두 가지만**: 도메인 이벤트(`EventBus` 프로토콜, v1은 in-process, 분리 시 Redis Streams/Kafka로 교체)와 읽기 전용 조회 인터페이스. 분산 트랜잭션 없음(이벤트는 outbox 테이블로 at-least-once, 소비자는 멱등).

**MSA로 넘어가는 조건 (하나라도 생기면 해당 컨텍스트만 분리)**
1. 배포 주기나 확장 요구가 다름(예: decode만 워커 10배).
2. 팀이 둘 이상이라 코드 소유권을 나눠야 함.
3. 한 컨텍스트의 장애가 다른 것을 멈춤(STT 폭주 → 로그인 지연).

**첫 분리 연습 (v1.1)**: notify를 독립 서비스로. Redis Streams(또는 Kafka)로 `RecordingDone`·`ActionDue`를 받아 APNs를 쏜다. 분리 전후 지연·장애 격리 수치를 기록한다. 처음부터 5개로 쪼개지 않는다.

**폴더 = 컨텍스트 (개정 2026-09-21, FD-7, Backend B-0·B-1)**: MSA 분리가 "폴더 하나를 옮기는 것"이 되려면 컨텍스트가 최상위여야 한다. 층은 컨텍스트 안에서 유지.

## 18. 도커를 쓰는 이유 (질문에 대한 기록)

서버 프로세스 6개(api, worker, scheduler, MySQL, Redis, 스토리지)를 도커 없이 VM에 직접 설치하면 설치 스크립트가 더 복잡하고 로컬·dev·prod가 어긋난다. 도커의 비용(이미지 빌드 1~3분, 데몬 메모리 수백 MB, 파일 셋 관리)은 재현성·롤백·격리·확장 이점보다 작다. 앱은 해당 없음(Xcode). Kubernetes는 §12 트리거 전엔 쓰지 않는다.

## 19. 비용 집계 파이프라인 (신설 2026-09-21, FD-6·FD-7, Backend B-2, ADR-0009, REQ-13)

**세 층**: 호출 단위 원시 기록 `ai_usage` → 일 배치 `usage_daily` → `eval/cost_model.py` 입력. 앱이 온디바이스로 처리한 요청(v1.1 `engineHint`)도 세어야 온디바이스 비율이 원가에 반영된다.

**dbml v1.1 문안(마이그레이션 0002, Day 11. PII 없음 — 텍스트 컬럼 0개, `user_id`는 기존 대리키)**
```dbml
Enum ai_task    { DETECT_PLAIN  NUANCE_ACTIONS  QUIZ_DISTRACTOR  MEETING_SUMMARY  STT_CHUNK }
Enum ai_engine  { GEMINI_FREE  OPENAI_KEY  ANTHROPIC_KEY  VLLM_LOCAL  NONE  ON_DEVICE  WHISPER_LOCAL
                  GROQ_WHISPER [note: 'v1.1, 약관 확인 후']  GEMINI_AUDIO [note: 'v1.1, 약관 확인 후'] }
Enum ai_outcome { OK  TIMEOUT  PROVIDER_5XX  RATE_LIMITED  BAD_JSON  QUOTA_SKIP  BREAKER_SKIP  BUDGET_SKIP
                  CONSENT_SKIP [note: '미동의 → none (FD-4)'] }
Enum engine_hint { SERVER  ON_DEVICE_PARTIAL  ON_DEVICE_FULL }

Table ai_usage {
  id             bigint        [pk, increment]
  request_id     char(36)      [not null, note: 'X-Request-Id (Caddy). 앱 Sentry 이벤트와 결합']
  user_id        bigint        [not null]
  translation_id bigint        [note: '저장 후 연결. 실패·퀴즈·STT는 NULL']
  recording_id   bigint        [note: 'STT_CHUNK일 때']
  task           ai_task       [not null]
  engine         ai_engine     [not null]
  model          varchar(50)   [not null, note: '실제 모델 ID. NONE은 "dictionary", ON_DEVICE는 앱 보고값']
  engine_hint    engine_hint   [not null, default: 'SERVER']
  consent        boolean       [not null, default: false, note: 'X-Mw-AI-Consent 헤더 (FD-4)']
  client_os      varchar(12)   [note: '"iOS 17" 같은 메이저까지만 (User-Agent)']
  input_tokens   int           [not null, default: 0]
  output_tokens  int           [not null, default: 0]
  cached_tokens  int           [not null, default: 0]
  audio_sec      int           [note: 'STT_CHUNK 입력 길이(초)']
  latency_ms     int           [not null]
  outcome        ai_outcome    [not null]
  fallback_from  ai_engine     [note: '이 호출이 폴백이면 원래 1순위 엔진']
  cost_usd       decimal(10,6) [not null, default: 0, note: 'pricing.toml 단가 × 토큰 (무료 티어는 0)']
  list_cost_usd  decimal(10,6) [not null, default: 0, note: '무료 티어를 정가로 환산 — 손익분기 계산용']
  price_version  varchar(20)   [not null, note: 'eval/pricing.toml verified_on']
  prompt_version varchar(20)   [not null, note: 'decode/domain/prompts.py PROMPT_VERSION']
  created_at     datetime      [not null, default: `now()`]
  indexes { created_at [name: 'ix_ai_usage_time']  (engine, model, created_at) [name: 'ix_ai_usage_engine_time']
            (user_id, created_at) [name: 'ix_ai_usage_user_time']  translation_id [name: 'ix_ai_usage_translation'] }
  Note: 'AI·STT 호출 1건 = 1행. 텍스트 컬럼 없음(원문·프롬프트·응답 금지, REQ-14). 90일 보존 후 삭제, 집계는 usage_daily에 남음'
}

Table usage_daily {
  date            date          [not null, note: 'UTC 기준 일자 (무료 한도 창과 동일)']
  engine          ai_engine     [not null]
  model           varchar(50)   [not null]
  task            ai_task       [not null]
  calls           int           [not null, default: 0]
  ok_calls        int           [not null, default: 0]
  fallback_calls  int           [not null, default: 0]
  consent_calls   int           [not null, default: 0, note: '옵트인 비율 산출']
  input_tokens    bigint        [not null, default: 0]
  output_tokens   bigint        [not null, default: 0]
  cached_tokens   bigint        [not null, default: 0]
  audio_sec       bigint        [not null, default: 0]
  latency_p50_ms  int
  latency_p95_ms  int
  cost_usd        decimal(12,6) [not null, default: 0]
  list_cost_usd   decimal(12,6) [not null, default: 0]
  distinct_users  int           [not null, default: 0, note: '그날 이 (engine,model,task)를 쓴 사용자 수 — MAU 분모']
  price_version   varchar(20)   [not null]
  computed_at     datetime      [not null, default: `now()`]
  indexes { (date, engine, model, task) [pk]  date [name: 'ix_usage_daily_date'] }
  Note: 'ai_usage 일 집계. ARQ cron aggregate_usage_daily 가 멱등(UPSERT). eval/cost_model.py 입력'
}
Ref: ai_usage.user_id > users.id
Ref: ai_usage.translation_id > translations.id
Ref: ai_usage.recording_id > meeting_recordings.id
```

**배치**: ARQ cron `aggregate_usage_daily` 매일 00:10 KST(전날 UTC 하루가 닫힌 뒤), `INSERT … SELECT … GROUP BY ON DUPLICATE KEY UPDATE`(멱등), 실패 시 다음 날 최근 3일 재집계. `purge_ai_usage` 매일 03:10(`created_at < now − 90d`). p50/p95는 파이썬 집계(행 수 수천). Day 25(NEW-19).

**`eval/cost_model.py`가 읽는 것(FD-6)**: `pricing.toml`(단가·무료 한도 `rpd`/`rpm`/`tpm`/`audio_sec_per_day`·`verified_on`·출처), `usage.toml`(가정) 또는 `eval/measured/usage.toml`(`usage_snapshot.py`가 `usage_daily`에서 생성, 비공개). 측정값 = 작업별 평균 input/output/cached 토큰, 폴백·강등·옵트인 비율, 온디바이스 비율(`engine=ON_DEVICE`, v1.1), STT 초/녹음. 산식은 §15-5. 테스트 벡터 `packages/test-vectors/cost_model.json`. 대시보드는 Grafana MySQL 데이터소스로 `usage_daily` 직접(추가 서비스 없음). `price_version`이 30일 이상이면 CI 경고. 행 폭증(MAU 5천+) 시 `ai_usage` 보존 30일로 단축(설정).
