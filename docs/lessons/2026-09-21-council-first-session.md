# 배운 점 — 협의체 1차 세션 (2026-09-19 메모 → 2026-09-21 확정)

> REQ-21. 형식: 상황 → 배운 것 → 다음부터 규칙. 근거는 `docs/council/S0-redteam.md`와 각 ADR.

## 1. 파트 견적 합산 없이 PM 견적을 신뢰하지 않는다
- **상황**: PM은 신규 REQ 순증을 +10.5일로 잡고 −8.5일을 잘라 "잔여 −3.0일, 버퍼 0"으로 마감했다. 레드팀 B가 7개 메모의 "v1.0에 넣겠다"는 항목을 그대로 합치니 ≈ 28~31일(중복 제거해도 ≥ 20일) — PM의 2.5배(RT-B-01). PM이 v1.1로 뺀 것(OCR, STT 미리보기, 라이브 액티비티, macOS 로컬 알림)을 다른 파트가 v1.0으로 다시 넣고 있었다(RT-A-11).
- **배운 것**: 파트 메모는 각자 자기 답으로 일정을 잡는다. PM 표에 없는 작업은 "없는 것"이 아니라 "안 보이는 것"이다.
- **규칙**: 각 파트가 자기 v1.0 항목을 PM 표의 Day 번호에 **직접 매핑**한다(Day에 못 붙는 항목 = 자동 v1.1). PM은 재합산해 "순증 ≤ 감축"을 증명한 합산표 1장을 내야 착수. 협의체 치명 기준에 "1인 견적이 잔여 시간 초과"를 스스로 적용한다.

## 2. 무료 티어 약관은 기능 결정 전에 읽는다
- **상황**: AI 파트만 Google 약관을 확인했다("Do not submit sensitive, confidential, or personal information to the Unpaid Services", 개선에 사용, 인간 검토). PO는 그 사실을 "확인 필요·베타 전 게이트"로 되돌렸고, Backend·PM은 인지 없이 무료 Gemini를 prod 1순위로 박았다(RT-A-01·RT-B-10 치명). Groq 오디오 약관은 아무도 안 읽었다(RT-B-11).
- **배운 것**: "무료"는 돈이 아니라 데이터로 값을 치른다. 약관을 읽지 않은 파트가 사슬 순서를 정하면 유출 경로가 코드가 된다.
- **규칙**: 외부 서비스(AI·STT·관측)를 사슬에 넣기 전에 약관·데이터 사용 조항을 읽고 ADR 부록에 **인용문·URL·확인일**을 남긴다. 미확인이면 사슬에 없다(ADR-0008 부록 A). 서버 기본값은 "안 보냄"(`AI_EXTERNAL_TEXT=off`).

## 3. `@Entry` back-deploy 오해 — API 가용성은 문서로 확인하고 결정 표를 고친다
- **상황**: 15번 T-C2는 "17+면 `@Entry`를 잃는다"를 26 only의 근거 중 하나로 썼다. Apple 문서: `@Entry`는 iOS 13.0+ / macOS 10.15+(매크로가 `EnvironmentKey` 코드를 생성하므로 back-deploy, Xcode 16 툴체인). 폴백이 정말 필요한 API는 30개 중 7개뿐이었다(iOS A-4).
- **배운 것**: "최신 OS만"의 근거가 사실은 툴체인 요구사항이었다. 결정 표의 한 칸이 틀리면 결정 전체가 기울어진다.
- **규칙**: Apple API 최소 OS는 sosumi/apple-docs로 확인하고 "Available on" 값을 표에 적는다. 확인 못 하면 "확인 필요". 레드팀은 "[사실]" 표기를 전수 재검증한다(1차: 28건 중 오류 2).

## 4. `sidebarAdaptable`은 iPadOS에서 우리가 원한 모양이 아니다
- **상황**: D-17은 `TabView` + `.sidebarAdaptable` 루트 하나를 전제했다. Apple 문서: iOS 18 / macOS 15+이고 "iPadOS displays a top tab bar that can adapt into a sidebar" — 사이드바 고정이 아니라 상단 탭바가 기본. REQ-01 "iPad = 사이드바·세 열"과 맞지 않았다(RT-A-09).
- **배운 것**: API 이름이 요구사항 단어와 같아도 플랫폼별 렌더링을 읽어야 한다. 최소 OS 문제가 아니었어도 쓰면 안 되는 API였다.
- **규칙**: 루트·내비 API는 Discussion 절의 플랫폼별 동작까지 읽고 스크린샷/문서 인용을 결정 근거에 붙인다. `sidebarAdaptable` 미사용, compact `TabView` / wide `NavigationSplitView` 2벌(ADR-0006).

## 5. `@SceneStorage`는 `RawRepresentable`만 받는다 — 타입까지 확인한다
- **상황**: MI-2가 `@SceneStorage("mw.sidebar") var sidebar: NavigationSplitViewVisibility = .all`을 썼다. `NavigationSplitViewVisibility`는 `Codable/Equatable/Sendable`만 채택하고 `SceneStorage.init`은 Bool/Int/Double/String/URL/Data 또는 `RawRepresentable`(Int/String)만 받는다 → 컴파일 불가(RT-A-10). 12번 §8의 `[Tab: [AppRoute]]` 저장도 같은 문제였는데 아무도 적지 않았다.
- **배운 것**: "가용 OS"만 확인하고 "타입 제약"을 안 보면 코드 한 줄이 설계를 무너뜨린다.
- **규칙**: 프로퍼티 래퍼·제네릭 API는 초기화자 시그니처(제약)까지 문서에서 확인한다. v1.0은 `@State`(창 수명), v1.1 String(JSON) 래퍼(F-4).

## 6. hosted `macos-26`은 GA이고 `macos-14`는 11/2에 사라진다 — CI 사실은 출처와 함께
- **상황**: 현재 `app.yml` 주석은 "hosted macos-15는 macOS 26 테스트 불가 → self-hosted 필요"였다. QA가 `macos-26` GA(2026-02-26)·`macos-14` 폐기(2026-07-06~11-02)·공개 저장소 무료를 찾았지만 출처 URL·확인일 없이 "[사실]"로 적었고(RT-B-21), iOS 메모는 "hosted macOS 10배 과금"(비공개 규칙)을 전제로 self-hosted를 PR 기본으로 둬 fork PR 코드가 개발 Mac에서 실행되는 경로를 열었다(RT-B-20). Xcode 핀 26.5 ≠ 보유 26.4, 런타임 17.5 ≠ 설치된 17.0.
- **배운 것**: CI 결정은 러너 이미지·과금 규칙·보유 툴체인 세 가지 사실 위에 서고, 셋 다 바뀐다.
- **규칙**: 러너 이미지·폐기 일정·과금은 actions/runner-images README·GitHub Docs URL과 조회일을 ADR에 적는다. Xcode 핀은 개발 Mac 보유 버전과 같게. self-hosted는 `pull_request`에 절대 배정하지 않는다(ADR-0011). 저장소 공개 여부는 CI 비용 전제이므로 ADR에 명시.

## 7. 파트 간 스키마 3벌 → 단일 원본 파일 규칙
- **상황**: `contracts/push-payload.json` 하나에 대해 MN-1(중첩 `mw` + `deepLink`), Backend(평면 키, `deepLink` 없음), PO(평면 + 다른 카테고리명) 세 스키마가 제출됐다(RT-A-03 치명). `aiModel` 규약 3개(RT-A-04), 넓은 화면 환경값 이름 3·식 3(RT-A-08), 평가셋 파일·스키마·위치 4벌(RT-A-06), 비용 계산기 2벌(RT-A-07), 스냅샷 매트릭스 4벌(RT-B-05), 무료 RPD 가정 4벌(RT-B-13). 치명 8건 중 5건이 "같은 문제에 파트마다 다른 답" 유형.
- **배운 것**: 병렬로 쓰는 메모는 반드시 겹치고, 겹친 곳은 코드에서 Day 18과 Day 24가 각자 다른 스키마를 구현하는 사고로 끝난다.
- **규칙**: 여러 파트가 건드리는 파일·스키마·수치는 세션 초반에 **소유자 1명 + 파일 1개**를 정하고 다른 파트는 인용만 한다. 파트 메모끼리 다르면 세션 FD 파일이 이긴다(`docs/council/README.md` §7). 결정의 단일 원본은 `S{n}.md`, 최종 형태는 ADR.

## 8. 협의체 시간 상한 — 첫 세션은 이틀이 걸렸다
- **상황**: 메모 7개(합 ≈ 3,400줄) + 레드팀 2개 + 사용자 결정 + ADR 8개 정리에 9/19~9/21 이틀. PM-5의 상한은 사람 시간 1.5h/세션, 결정 ≤ 5개, 산출물 2,000자 요약.
- **배운 것**: 상한 없이 "전부 다루자"는 결정 47건(치명 8·중요 27·경미 16)을 한 번에 만들고, 그중 형식 미달(7항목 없음)이 여럿 생긴다.
- **규칙**: 세션당 결정 ≤ 5, 사람 시간 1.5h. 넘치면 다음 세션. 2회 연속 초과 시 격주(REQ-25 상태 갱신). 파트 메모는 2,000자 요약 + 원문 첨부(`S{n}/`).

## 9. 형식(REQ-20 7항목)이 빠진 결정은 무효로 한 것이 옳았다
- **상황**: AI-5·AI-6는 요약표 한 줄, MN-3·MN-4는 표·목록, Backend B-6 ②(ENUM 전략)는 의도·대안 없이 "미리 넣자", QA §2-3·§4는 영향·검증·되돌림 누락(RT-A-14·RT-B-23). B-6 ②는 그대로 갔으면 dbml v1.0 변경(RT-A-16)이었다.
- **배운 것**: 대안·검증·되돌림이 없는 결정은 대개 다른 파트와 충돌하거나 계약을 깬다. 형식은 관료주의가 아니라 검출기다.
- **규칙**: 7항목이 없으면 결정이 아니라 "ADR 초안 재료"로 표기한다. ADR로 옮길 때 채운다(ADR-0007 §4-6·4-7, ADR-0010 §4-4·4-5).

## 10. 비용 산식은 돌려 봐야 한다 — 레드팀이 계산기를 실행해 오류 3개를 찾았다
- **상황**: PO의 `cost_model_draft.py`는 정상 종료했지만 무료 한도를 `RPD×30`으로 월 평균화(소진 MAU 94 → 141 과대, 피크 RPM 3.6배 과소), 온디바이스 비율 이중 적용(iOS 17~25 서버 몫 0원), 고정비 t4g.small 15$(PM은 OCI Free)로 결론 숫자가 전부 흔들렸다(RT-B-08·14·15). PO-2 "녹음 유료"의 근거 65%는 가정 단가 파일에서만 나왔다(RT-B-09).
- **배운 것**: 코드가 돌아가는 것과 산식이 맞는 것은 다르다. 가정 단가로 만든 숫자를 "정책 상수"로 승격하면 안 된다.
- **규칙**: 산식은 근무일·근무시간 단위, 비율은 한 번만, 고정비는 실제 결정과 일치. 손계산 벡터·경계·항등식 테스트 필수. 가정값은 `source = "assumption"`으로 표기하고 BM 문서에서 "가정"으로 인용(ADR-0009, `docs/bm/early-strategy.md`).

## 11. "사용자 제공 키"처럼 REQ 문구가 해석을 낳으면 REQ 각주로 닫는다
- **상황**: REQ-11의 "OpenAI·Claude는 사용자 제공 키"를 Backend는 운영자 `.env` 키, AI는 최종 사용자 BYOK, PO는 평가 전용으로 읽었다(RT-B-12). Backend 해석은 결제 발생 경로였다.
- **배운 것**: REQ 한 줄의 애매한 명사는 세 파트에서 세 설계가 된다.
- **규칙**: 해석이 갈린 REQ는 사용자에게 올려 답을 받고 REQUIREMENTS에 각주로 박는다(REQ-11 각주 (2)). 레드팀은 "사용자 결정 필요 목록"(U-1~U-20)을 표로 모아 올린다.

## 12. 사용자 답변이 오면 파트 문서의 트리거·되돌림 조건을 즉시 갱신한다
- **상황**: BRIEF에 "공휴일 전부 근무 / Mac 26 + Apple Intelligence / Xcode 26.4, iOS 17.0 런타임 설치됨"이 답변됐는데 PM §7 확인 필요 3건·리스크 #1·#2·PM-2 되돌림("런타임 설치 불가 → 18/15")이 그대로였고, QA·iOS 매트릭스는 17.5·26.5를 썼다(RT-B-06·RT-A-20).
- **배운 것**: 답변 이후에도 옛 전제로 쓴 문장이 살아 있으면 다음 세션에서 다시 논의된다.
- **규칙**: 사용자 답변 원문을 `S{n}.md`에 적고, 그 답으로 소멸한 트리거·되돌림 조건을 같은 세션에서 지운다(ADR-0005 대안 ②, ADR-0011 런타임 17.0).
