# 2026-10-27 해석 기능 레드팀(QA) 3라운드 — 기록

v1.0 해석 흐름(서버 #12·#36·#11, 앱 #14·#15·#10·#25)을 기능 하나 끝날 때마다 레드팀(=QA)에 넘겼다.
레드팀은 고치지 않고 재현·원인(파일:줄)·고치는 법만 보고했다. 수정은 개발 쪽이 하고 회귀 테스트로 묶었다.

## 배운 점
1. **오탐 경계는 '글자'가 아니라 '문자열'로 본다.** "로"를 허용하면 "싱크로율", "에"를 허용하면 "밸류에이션"이 잡힌다. 조사는 사슬이 낱말 경계에서 끝날 때만, 활용(하다·받다·드리다)은 뒤와 상관없이.
2. **동시성 버그는 SQLite가 숨긴다.** 첫 해석 경합은 SQLite 에선 통과했고, 레드팀이 InnoDB 잠금을 근거로 예측한 교착(1213)을 CI MySQL 8동시 테스트가 실제로 잡았다. 원인: INSERT 의 외래 키 확인(공유 잠금) → UPDATE(배타) 승격 경합. 사용자 행을 먼저 FOR UPDATE.
3. **고친 것이 새 버그를 만든다.** "동의하면 재사용 안 함"은 외부 엔진이 꺼진 환경에서 중복 저장(High)이 됐다. 수정마다 2차 검증을 돌린 이유.
4. **앱은 스크린숏 픽셀 측정이 말보다 정확하다.** "거의 같다"였던 결과 시트가 측정해 보니 +29pt(같은 여백이 두 번 붙음), 탭 바는 안전 영역만큼 떠 있었다.
5. **직접 로그아웃과 세션 만료를 구분한다.** 상태를 먼저 바꾸지 않으면 로그아웃 순간 나간 요청의 401 이 "로그인이 풀렸어요"로 보인다.
6. **macOS SDK 이름 충돌**: SwiftUI 가 다시 내보내는 `Translation` 때문에 우리 `Translation` 이 모호해졌다 → `Domain.Translation`.
