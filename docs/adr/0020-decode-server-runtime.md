# ADR-0020: 해석 서버 런타임 — 사전 간이 해석 바닥, Redis(redis-py) 공유 한도·브레이커, 로컬 전용 개발 로그인

- 상태: 채택 (2026-10-27)
- 관련: ADR-0003(블루그린)·0007(AI 4트랙)·0008(원문 외부 전송)·0014(Apple 로그인)·0018(판교어 탐지), REQ-11·14·20, #11·#12·#36·#110, 14번 §15-3

## 맥락
- v1.0 해석(Day 6~8)을 끝까지 돌리려면 ① AI 키·옵트인이 없을 때도 결과가 나와야 하고 ② 블루·그린 두 색 × 워커 여러 개가 같은 무료 한도·브레이커를 봐야 하며 ③ Apple 키(.p8)가 없는 지금도 시뮬레이터 E2E·계약 검사(성공 경로)가 돌아야 한다.
- 계약 v1.0(`openapi.yml`, `db.dbml`)은 고정이다. 새 테이블·컬럼·응답 코드를 만들 수 없다.

## 결정
1. 엔진 사슬(prod): `gemini_free`(옵트인 헤더 `X-Mw-AI-Consent: 1` && `AI_EXTERNAL_TEXT` 켜짐 && 키 && 브레이커 닫힘 && 80% 소프트 한도) → `none`. 외부 실패는 재시도 없이 바로 `none`(`ROUTER_ALLOW_DEGRADED`, 끄면 503 + Retry-After).
2. 사전 매칭 인덱스는 유니코드 스칼라. 정답 벡터 `packages/test-vectors/jargon_match.json`을 서버·앱이 같이 읽는다.
3. 시드 사전 134개는 `app/decode/infra/seed_terms.py`가 원본이고 Alembic 0002(데이터만)와 로컬 SQLite가 같은 함수로 넣는다. 이형 표기(aliases)는 DB 컬럼이 없어 이 파일에만 있다(v1.1 계약에서 컬럼 검토).
4. 한도 키 `ai:quota:{engine}:{model}:{rpm|rpd}:{window}`, 브레이커 키 `ai:breaker:{engine}:*`. 값에 원문·사용자 ID 없음. prod 는 `MWONMAL_REDIS_URL` 없으면 기동 거부.
5. `scripts/dev_server.py`(SQLite + 시드 + 개발 로그인)로 앱 E2E와 CI 계약 검사를 같은 방식으로 돌린다.

## 근거 (2026-10-27)
- pytest 179 통과. schemathesis 11개 연산 1,075 케이스 통과(로그인 토큰으로 2xx 스키마 포함). 계약 예시 문장의 하이라이트 인덱스(8–14, 17–20, 31–34, 40–43)가 그대로 나온다.
- 카나리 테스트: 성공·실패 경로 모두 원문이 로그에 0회.

## 결과
- 쉬워짐: 키·옵트인 없이도 해석·할 일·기록 화면이 실제 데이터로 돈다. 계약 검사가 성공 응답까지 본다.
- 어려워짐: 규칙 엔진의 할 일 추출은 문장 끝 패턴뿐이라 놓치는 경우가 있다(eval 하네스로 측정, #37). 개발 로그인 설정이 실수로 켜지지 않게 기동 검사를 유지해야 한다.
- 되돌리는 조건: Redis 장애가 잦으면 브레이커만 메모리로(한도는 보수적으로 50%) 강등한다.
