# ADR-0003: 서버 무중단 배포는 블루·그린(Caddy upstream 전환)으로

- 상태: 채택 (2026-09-19)
- 관련: 설계 13번 §5-2, 14번 §12, 이슈 #5

## 맥락
단일 VM, Docker Compose. `compose up`은 컨테이너 교체 중 수 초 다운이 생긴다. 앱은 GET만 자동 재시도하므로 배포 중 POST(해석·조각 업로드)가 실패할 수 있다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 재시작 허용 | 가장 단순 | 수 초 5xx, 녹음 조각 재시도 유발 |
| 롤링(레플리카 2+) | 표준 | Compose에서 레플리카 관리가 어색, VM 1대에선 의미 반감 |
| 블루·그린 | 새 색을 띄우고 `/ready` 확인 후 프록시만 전환, 즉시 롤백 | 컨테이너 2세트 메모리, 스크립트 필요 |

## 결정
`api_blue`/`api_green` 두 서비스, Caddy admin API로 upstream 전환. 순서: 새 색 `up` → `/ready` 폴링 → Caddy 전환 → 옛 색 30초 drain 후 `stop`. 워커는 `--scale`로 새 것 먼저 띄운 뒤 옛 것 정지(작업은 멱등). 마이그레이션은 expand/contract(호환 변경만 배포 전, 파괴 변경은 다음 릴리스).

## 근거
VM 1대에서 무중단을 얻는 가장 싼 방법. 롤백은 upstream을 되돌리는 한 명령.

## 결과
쉬워짐: 배포 중 5xx 0. 어려워짐: DB 스키마가 두 버전과 호환되어야 한다(expand/contract 규칙 준수).

## 되돌리는 조건
VM 2대 이상이 되면 로드밸런서 뒤 롤링으로 교체.
